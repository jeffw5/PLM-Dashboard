Top-down meaning from the holarchy meets bottom-up structure from every source schema. A persistent mapping graph joins them, virtual graphs query them in place, and an AI fabric grounds each question in canonical URIs, so planned and on-demand analytics draw on one semantic layer.

On-demand analytics through the AI fabric. Each question is decomposed into WHO / WHAT / WHEN / WHERE / WHY (GOV-011), every phrase is grounded to a canonical URI through the RAG anchor index (GOV-010), and the virtual graph query runs against the sources in place. The same Policy Enforcement Points that govern transactions (GOV-012) and the ontology’s privacy shapes check the result before anyone sees it. Ungrounded phrases trip the circuit breaker (GOV-014).

Planned and on-demand analytics are two paths over one semantic layer. Planned analytics compile ahead of time and run with zero graph latency (GOV-024). On-demand analytics are assembled at question time through the virtual graph. Both pass the same PEPs, and questions that keep coming back get promoted into governed metrics.

The backup demo: what happens when a source changes under the semantic layer. The anti-drift lineage agent (GOV-006) detects the change, the Schema Diff Classifier grades it, and the impact is traced up the holarchy and out to every model, dashboard and cached answer that depends on it, before anyone notices a wrong number.

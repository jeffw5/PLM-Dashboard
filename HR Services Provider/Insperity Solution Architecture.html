Context

Author every rule once. Enforce it everywhere. Trace every answer back to the law.

Insperity carries statutory obligations for 300,000+ worksite employees across thousands of client companies, five service domains and every U.S. jurisdiction. This architecture puts a thin, standards-based governance layer above the existing HR, payroll, benefits and analytics systems. Rules are authored once as canonical truth (OWL / LKIF / SHACL), compiled into the engines that already run the business (dbt/SQL, OPA/Rego, agent guardrails), and every employee gets a governed personal model. Jarvis becomes the surface of that structure: every answer traceable, every irreversible action gated.

Grounded in three inputs: the value proposition (nine capabilities), the IIH roadmap (four gated phases over 18 months) and the policy & governance corpus (142-rule SSOT register across five domains plus PEO standards).

End-to-end flow

Both converge on the SSOT rule registry and personal models, which the RDSG gateway uses to govern every payroll run, benefits decision and Jarvis answer.

Canonical stages

Definition-time and run-time are kept apart (GOV-001). Canonical truth lives in the graph; the business runs on compiled projections that execute in microseconds and carry the source URI with every decision.

Pipeline A — Policy & rules

A1
Author
Legal architects express a statute as an LKIF obligation / permission / prohibition plus a SHACL shape, bound to an ORSD.
A2
Validate
Shape tests against golden records; ORSD competency questions must pass.
A3
Harmonize
SPARQL conflict scan; highest-employee-protection wins (GOV-009).
A4
Compile
Parse → extract → target-map → generate dbt tests, SQL checks, Rego, JSON-Schema directives.
A5
Publish
KGCL-stamped release through DEV/STG/PRD gates; training triggers fire on change.
A6
Enforce
PEPs at the gateway and in payroll/benefits runs; every rejection cites its rule URI.

Pipeline B — Knowledge admission

B1
Ingest
Connect Box AI and live feeds; preserve source and tenant.
B2
Profile
Classify asset type, owning client, PII/PHI class, currency.
B3
Enrich
Extract plans, eligibility terms, jurisdictions, effective dates.
B4
Admit
SHACL admission gate; failures quarantined with KGCL rejection.
B5
Bind
Attach deontic norms; link to rules, personal models and clients.
B6
Index
Hybrid vector + SPARQL index, grounded on canonical URIs.

4

Holonic semantic layer

Five levels, each with a defined contract to its neighbours. Each domain is a sovereign holon — ontology, agent, hybrid vector DB, PEPs with LKIF norms, MTBH monitor — so adding the sixth domain never touches the first.

L4
Enterprise holarchy
Semantic Governance Council & CoE, ARB change review, DEV/STG/PRD lifecycle (GOV-002, GOV-003). Holds SKOS vocabularies, upper and value-stream ontologies, and the standards scaffold: ISO 8000, OMG ODM/DOL/DPROD, LKIF.
Lateral
Mediation holon
Persistent mapping graph (six correspondence types to dbt, LookML, Neo4j, vector stores, with anti-drift lineage) · identity & URI resolution registry (GOV-007) · rule harmonization engine (GOV-008) · rule projection agents (GOV-019) · RAG anchor index (GOV-010).
L3
RDSG gateway holon
5D Requirement Context Bundle — WHO · WHAT · WHEN · WHERE · WHY (GOV-011) · PEPs for compliance, risk, legal, security, data and AI governance (GOV-012) · STPA/STAMP unsafe-control-action checks (GOV-013) · MTBH circuit breaker (GOV-014) · Simplex action gates on irreversible actions (GOV-015).
L2
Domain holons
isp-pay Payroll & Tax · isp-ben Benefits · isp-comp Compliance & Risk · isp-tal Talent · isp-tech HR Technology — plus Client Relationship and (Phase 3) Contractor holons, all federated to isp-core by owl:imports (GOV-005).
L1
Knowledge holons
Atomic governed assets: one statute clause, one plan provision, one handbook policy — each with a URI, SHACL-validated, KGCL-versioned, and bound to the deontic norm that governs it.

Worked example · CA daily overtime (PAY-005/006)

# definition-time (isp-pay)
isp-pay:CADailyOvertimeNorm a lkif:Obligation ;
  lkif:isSubjectTo "CA Labor Code §510" ;
  isp-core:jurisdiction "US-CA" ;
  isp-pay:dailyThresholdHours 8.0 ; isp-pay:rateMultiplier 1.5 ;
  isp-pay:excessDailyThresholdHours 12.0 ; isp-pay:excessRateMultiplier 2.0 .
-- run-time: compiled dbt test (KGCL_2026_PAY_CA_0817)
WHERE jurisdiction='US-CA' AND worker_classification='NON_EXEMPT'
  AND ((daily_hours>8 AND daily_hours<=12 AND multiplier<1.5)
    OR (daily_hours>12 AND multiplier<2.0))

The same norm also compiles to an OPA/Rego gateway policy. Both artefacts carry …/payroll#CADailyOvertimeShape, so any rejected timesheet points to the exact statute behind it.

NIST AI RMF · ISO/IEC 42001 · NYC Local Law 144 · Colorado AI Act. Jarvis earns autonomy phase by phase (Observe → Advise → Assist → Governed Autonomy); MTBH targets rise from ≥95% to ≥97% per dimension, and the Simplex gate holds every irreversible action for a human in every phase.

7

Personal models, training & values

The value proposition's people-side capabilities, built on the same rule graph. A person's compliance state is a query, training is an event triggered by rule change, and values are measured like any other trust signal — within explicit privacy limits.

Governed personal model

One profile per employee and role: role, jurisdiction, competencies, training record, applicable rules, compliance state. Modeled in isp-core/isp-tal, keyed by the canonical Worksite Employee ID.

Projects: ISP-18 · rules TEC-005, TEC-010, TEC-011, TAL-017

On-demand compliance training

A published rule change (KGCL) or a role/jurisdiction change in the personal model assigns the right module automatically — CA SB 1343, NY annual, SB 553 WVPP — and completion evidence is written against the rule URI.

Projects: ISP-19 · rules TAL-012, TAL-013, TAL-017, CMP-005

Continuous values measurement

Values training encoded as a versioned rule set; alignment calibrated continuously from sanctioned signals (training outcomes, acknowledgments, surveys), not asserted once at onboarding.

Projects: ISP-23 · rules TAL-009, TEC-010

Privacy safeguards (non-negotiable)

No covert or content-level surveillanceConsent tracked per purpose (TEC-010)Data minimization (TEC-011)Masking / tokenization (TEC-012)Aggregate-only analytics for valuesTenant-scoped: never cross-clientEmployee can see their own model

Integration topology

Connect, don't rebuild. Existing platforms stay; the governance layer sits above them and projects rules into them.

Sources (integrate)

  • Box AI content cloud — 33M records
  • Payroll engine & time capture
  • Carrier EDI 834, 401(k) recordkeepers
  • ATS, LMS, background-check vendors
  • Regulatory feeds & statute watch

Semantic substrate

  • Triple store — isp-core + 5 domain ontologies
  • SHACL / SWRL / LKIF norm library
  • Hybrid vector DB per domain (GraphRAG)
  • Identity & URI resolution registry (SAML)

Agent runtime

  • Domain agents (LangGraph, governed Claude)
  • RDSG gateway · PEPs · MTBH
  • Rule projection agents
  • MCP + REST/GraphQL machine APIs

Runtime enforcement

  • dbt / SQL in payroll & benefits pipelines
  • OPA / Rego at the API gateway
  • JSON-Schema directives for Jarvis
  • Workflow engine for notices & training

Consumption

  • Jarvis — Employee, Employer/HRBP, Service Rep, Executive
  • Client & employee portals
  • LookML / BI via governed definitions

Consolidate / retire

  • SharePoint handbook silos → L1 holons
  • Compliance tracking spreadsheets → isp-comp
  • Ad hoc reporting → governed dashboards
  • Paper case escalation → Service Rep Jarvis

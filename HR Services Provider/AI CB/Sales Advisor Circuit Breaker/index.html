Sales Advisor Circuit Breaker

The Sales Advisor runs as six cooperating agents that qualify a prospect, discover needs, configure a solution, price it, check the claims and write the proposal. The circuit breaker sits between those agents and anything they send or commit. It measures every decision against a reference model of the real business, weights the result by the client persona the advisor is talking to, and holds anything out of tolerance for a person to decide.

How a decision is measured

The breaker never inspects model weights. It treats each agent as a morphism h: Zagent → Zreal and measures only the boundary: what the agent saw, what it decided, and how far that decision sits from the reference picture of the business. Each decision passes through the same six layers, in order.

L0 · BOUNDARY

Capture the decision

The agent framework emits a decision envelope at the tool-call boundary: the output, the engaged persona, the evidence used and the model version. Nothing reaches a prospect or a system of record before this point.

Is this a decision we can see whole?
L1 · REFERENCE STANDARDS

Fetch the ruler

Keel supplies the pinned version of the hr: ontology, the persona model, the five context anchors for this decision and the guardrails that apply. These are versioned like code.

What does reality say this should look like?
L2 · INSTRUMENTS

Measure three distances

Ds compares the decision's asserted facts to the ontology. Db compares its output to the reference intent. Dr scores WHO, WHAT, WHEN, WHERE and WHY against the anchors, weighted by persona. Each carries an uncertainty budget.

How far off is it, and on which axis?
L3 · CONTROL

Apply tolerance and rules

Guardrails veto first. Then each distance is compared to its tolerance, which tightens with the decision's consequence and the persona's tolerance. Out-of-tolerance trends are tracked with control limits.

PASS, COMPLY, FREEZE or HALT?
L4 · HOLARCHY

Roll up to the agent and the chain

Decision verdicts set each agent's state: online, restricted or dropped. Fidelity multiplies along the sales flow, so a loss in pricing lowers confidence in the proposal that follows it.

Can this agent keep acting on its own?
L5 · TRUSTEE

Hand judgment to a person

Held decisions go to the review queue with the full chain of evidence. The reviewer's disposition is recorded in PROV-O and fed back: corrections reduce drift, recalibration restores the agent, overrides count against trust.

What does the accountable human decide?

Persona sensitivity

The seven client personas from the Outcome Benchmark are the lenses. Each weights the five dimensions differently and accepts a different amount of drift, so the same decision can pass for one buyer and freeze for another. A Finance Leader is most exposed to WHAT and WHEN errors in a quote; an Operations & Safety Leader to WHERE errors in a class code. These are proposed starting values, to be calibrated from benchmark importance ratings.

Architecture

The breaker is a gateway service inside the agent fabric, not a feature of any one agent. Agents on North Star cannot reach a system of action except through it, and it reads its reference standards from Keel rather than holding its own copy of the business rules.

  1. 1Channels and systems of record give the agents their live context.
  2. 2Every agent decision leaves North Star as an envelope and enters the gateway.
  3. 3The gateway reads the pinned reference standards from Keel for that decision.
  4. 4Released decisions continue to the systems of action.
  5. 5Held decisions go to the trustee; the disposition returns to the gateway.
  6. 6Every measurement and disposition is written to the metrology and provenance store.
  7. 7Accepted corrections pass the SHACL gate and ship to Keel as a new standards release.

Implementing in the agentic fabric

The breaker works only if no agent action can bypass it. In practice that means action tools (send email, write CRM, generate quote, attach contract) are exposed to agents only through the gateway, whether the agents run on North Star, inside Copilot or behind an MCP server. The gateway is stack-independent: it speaks a small envelope contract and reads standards over SPARQL, so it fits the Microsoft stack and HRScale without being tied to either.

Synchronous where it matters

Decisions with consequence wc ≥ 0.7 (pricing, certification claims, class codes, contract terms) and every decision with a guardrail are evaluated in line and held until verdict. Lower-consequence decisions are evaluated asynchronously and sampled.

Fail closed on guardrails

If the gateway or Keel is unreachable, guardrail-bearing and high-consequence decisions stop and route to the advisor. Low-consequence decisions continue in advisory mode, flagged for later review.

Pin the standards

Every evaluation names the Keel release it used. Standards change through the dev, test, stage and prod pipeline, with change records as triples, so any verdict can be replayed against the rules in force at the time.

Calibrate from the benchmark

Persona weights come from benchmark importance ratings grouped by context dimension; tolerances from satisfaction gaps. Control limits come from four to six weeks of shadow baselines, not from guesses.

Feedback through a gate

A reviewer's correction never goes straight into an agent. It is validated against the SHACL shapes, then released into Keel, so contaminated corrections cannot re-enter the reference standards.

One contract, many agents

The same envelope and verdict serve every agent family. HR Advisory 360 and later client-facing agents join by emitting envelopes and registering their decision types and personas.

Rollout

Each phase widens what the breaker is allowed to stop, and each one needs the evidence from the phase before it.

  1. Shadow

    Agents emit envelopes; the gateway measures asynchronously and acts on nothing. Builds baselines and the first control limits, and shows where personas disagree.

    Exit: stable baselines on all 20 decision types

  2. Advisory

    Verdicts appear in the advisor workspace and the review queue is staffed. Weights and tolerances are calibrated against reviewer agreement.

    Exit: reviewer agreement with verdicts above target

  3. Enforce high consequence

    Guardrails and wc ≥ 0.7 decisions are held in line. Agents can be restricted and dropped; fallback routes to the advisor.

    Exit: MTBH and false-hold rate within agreed bands

  4. Full enforcement and reuse

    All Sales Advisor decisions are governed. The gateway and standards are reused for HR Advisory 360 and other agent families on the fabric.

    Exit: second agent family onboarded on the same contract

Context

Two agentic pipelines, one semantic core, one scoring model

Project & program data (from many inconsistently-configured Jira projects) and lifecycle artifact documents (from many libraries) are each ingested by a chain of specialised agents, enriched against the Holonic Semantic Layer, evaluated by discipline / standard / governance skills, and converged into a single PLM ingestion model that feeds the assessment console. Operational dashboards monitor both pipelines and the defect burndown; a business-impact dashboard projects value uplift and ROI by mapping realised maturity onto the enterprise value fabric.

Canonical agent stages

Both pipelines follow one pattern so agents, telemetry, and governance are reusable. Stages differ only in their connectors and their skill set.

01
Extract
Pull raw records/documents from heterogeneous sources; preserve everything.
02
Profile
Identify each source, infer field/section semantics, canonicalise, run data-quality checks (source defects).
03
Enrich
Attribute phase / discipline / artifact and align to ontology via the semantic layer; score confidence.
04
Map
Bind enriched records to PLM model slots and shared targets.
05
Evaluate
Run discipline / standard / governance skills → conformance, defects (major/minor), risk.
06
Load
Write scores to the PLM model and registers; emit lineage and telemetry.

4

Holonic Semantic Layer

The shared reasoning substrate. Every enrichment, mapping, traceability, and causal-projection decision resolves against it, which is what lets inconsistent sources land in one coherent model.

What it holds

  • Ontologies — RDSG and HSGA v3.0 (OWL), constraints in SHACL, held in GraphDB value-kb.
  • Taxonomies & vocabularies — lifecycle phases, disciplines, artifact types, defect classes.
  • Holarchy — task → story → epic → initiative → project → program → portfolio holons.
  • Traceability graph — requirements ↔ Jira items ↔ artifacts ↔ tests ↔ decisions.
  • Causal graph — capabilities → processes → services → domains → value streams (for business impact).
  • RAG index — Pinecone embeddings (Avatar 2.0) for retrieval during attribution and skill evaluation.

What it does for the pipelines

  • Attribution — infers phase / discipline / artifact for records whose source doesn't say so.
  • Alignment — maps arbitrary source terms to canonical classes (the RDSG gateway).
  • Holon assignment — situates each record in the program holarchy for correct roll-up.
  • Traceability — links Pipeline A items to Pipeline B artifacts so a phase-artifact slot draws on both.
  • Causal reasoning — projects how a project's realised maturity propagates to business value.
  • Confidence — every inference is scored; low confidence trips the circuit-breaker (MTBH).

Reconciliation rule

A slot's assessment blends the Pipeline-A signal (Jira execution evidence) and the Pipeline-B signal (artifact conformance). Where they disagree beyond tolerance, the Reconciliation Agent lowers confidence and the circuit-breaker routes the slot to human review rather than silently averaging — the same MTBH posture the console's gate enforces downstream.

Defect & risk scoring model

Defect severity

Major — a standard-mandated element is missing or wrong; gate-tripping. Minor — a quality/style shortfall; advisory, accrues as debt.

Risk

Each defect gets likelihood × impact (1–5). Impact rises with criticality, phase (release-facing), and governance regime. Exposure bands: Low / Moderate / High / Critical.

Aggregation

Per artifact: conformance across skills − weighted defects → maturity (0–3) for the slot. Majors cap the achievable score; a major on a critical artifact is a hard gate in the console.
